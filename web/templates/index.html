SRS Specification Mapping (T1-PS7)

This web application implements all requirements defined in the Sensitive Data Leak Detector for APIs Software Requirements Specification (SRS Version 1.0):

FR-1.x Loading Supports .json, .jsonl, .txt, .log files, directory scanning, and inline payload strings.
FR-2.x Parsing Recursively traverses nested JSON structures, records exact paths (e.g. data.users[0].email), handles line numbers for text, and inspects embedded strings.
FR-3.x Detection Covers all 15 rules from Section 6.1: emails, phones (+91 & intl), passwords & hashes, API keys, JWTs, Bearer headers, AWS keys, PEM private keys, Luhn-validated credit cards, Aadhaar, PAN, DB URIs, and internal IPs.
FR-4.x Classification Assigns finding categories, severity tiers (Critical, High, Medium, Low), contextual escalation for admin roles, and calculates overall risk scores.
FR-5.x Masking Redacts all outputs according to type. Zero raw secrets are ever leaked or exported. Supports partial, full, and SHA-256 hash masking styles.
FR-6.x Advisory Provides plain-language risk explanations, actionable remediation steps, and maps to OWASP API Top 10 (2023), GDPR, and PCI-DSS.
FR-7.x Reporting Generates executive summaries and exports across HTML (with interactive charts), Markdown, CSV, and JSON formats.
REST API Integration Guide

Integrate this detector directly into your CI/CD pipelines or pre-commit hooks via standard REST endpoints:

1. Scan Payload String

curl -X POST http://localhost:5000/api/scan \
  -H "Content-Type: application/json" \
  -d '{"text": "{\"user\": \"alice@company.com\", \"token\": \"eyJ...\"}", "masking_style": "partial"}'

2. Upload File to Scan

curl -X POST http://localhost:5000/api/scan-file \
  -F "files=@samples/leaky_user_pii.json" \
  -F "masking_style=partial" \
  -F "min_severity=Medium"

3. CLI Tool Usage

python -m leakdetect.cli scan samples/leaky_auth_tokens.json \
  --rules rules/default_rules.yaml \
  --format html \
  --output report.html \
  --save-masked masked.json
